LabNote ELN - 시퀀스 다이어그램

전자연구노트(ELN) 협업 플랫폼의 핵심 흐름 8가지 시각화 문서

목차

1. 로그인 / 토큰 갱신 / 로그아웃 2. 연구노트 작성 및 저장 3. 실시간 협업 편집 4. 전자서명 → 상태 전환 5. 관리자 잠금 해제 6. PDF/ZIP 내보내기 7. 통합 검색 8. 인벤토리 수량 변경 및 재고 경고 부록: 서비스 아키텍처 / 이벤트 흐름
일반 단계
에러/분기 (alt)
비동기 처리
선택적 (opt)

3. 실시간 협업 편집

연구자 A (Alice)
연구자 B (Bob)
Collab Service
(:8009 WS)
Redis
(pub/sub)
1
Alice→Collab
WebSocket 연결 ws://.../collab/notes/{noteId}?token={jwt}
JWT 검증 → 방(Room)에 Alice 추가 (colorIdx: 0)
← {type:'joined', users:[]}
2
Bob→Collab
WebSocket 연결 → 방에 Bob 추가 (colorIdx: 1)
→ Bob: {type:'joined', users:[{id:'alice', colorIdx:0}]}
→ Alice: {type:'user-joined', userId:'bob', colorIdx:1}
Collab → Redis: PUBLISH labnote:collab {user-joined}
3
Alice→Collab
{type:'content-update', content:'실험 결과...'} (400ms 디바운스)
→ Bob: {type:'content-update', userId:'alice', content:'...'}
Bob은 1초 이내 자신의 편집이면 무시, 아니면 에디터에 반영 (last-write-wins)
4
Alice→Collab
{type:'awareness', cursorLine:15} → Bob에게 커서 위치 전파
5
Bob
WebSocket 연결 종료 → 방에서 Bob 제거
→ Alice: {type:'user-left', userId:'bob'}

4. 전자서명 → 상태 전환

검토자
(Reviewer)
Frontend
Signature-Audit
(:8003)
Auth
(:8001)
PostgreSQL
(sig)
Redis Stream
ELN
(:8002)
PostgreSQL
(eln)
1
검토자→Signature-Audit
POST /api/signatures/sign/:noteId {password, comment}
2
Signature→Auth
POST /api/auth/internal/verify-password {userId, password} (x-internal-secret) 비밀번호 불일치 → 400 SIGNATURE_PASSWORD_INVALID
3
Signature→ELN
GET /api/notes/:noteId (내부 호출) → 노트 정보 확인
4
Signature
권한 검증: 자기 서명 차단 (admin 제외), reviewer/admin/팀장 확인
5
Signature→PostgreSQL (sig)
이전 서명 조회 → 해시체인 생성: sha256(noteId:signerId:timestamp:prevHash:comment)
6
Signature→PostgreSQL (sig)
INSERT INTO signature (signatureHash, prevHash, chainIndex, status:'valid')
INSERT INTO auditLog (action:'signed')
7
Signature→Redis Stream
XADD labnote:events * type=NOTE_SIGNED noteId={id} status=signed Redis 실패 시 HTTP 폴백: PATCH /api/notes/:id/status {status:'signed'} (x-user-role: system)
8
서명자 ≠ 작성자 → 알림 생성: '연구노트가 서명되었습니다'
9
← 201 {ok:true, data:signature} → 서명 완료 안내
10
비동기 이벤트 소비 (Consumer Group: eln-service)
Redis → ELN: NOTE_SIGNED 이벤트 수신
ELN → PostgreSQL (eln): UPDATE note SET status='signed'
+ INSERT INTO noteStatusHistory (in_progress → signed)
+ INSERT INTO auditLog (이중 기록)
ELN → Redis: XACK labnote:events (처리 완료)

7. 통합 검색

사용자
Frontend
Search Service
(:8006)
Redis
(캐시)
OpenSearch
PostgreSQL
(search)
1
사용자 검색어 타이핑 (예: "세포 배양")
Frontend→Search GET /api/search/suggest?q=세포 배양
2
Search→OpenSearch
multi_match fields: title^3, tags^2, type: phrase_prefix, filter: orgId
← 상위 7건 → Frontend: 자동완성 드롭다운 표시
3
사용자 Enter 또는 검색 버튼 클릭
Frontend→Search GET /api/search?q=세포 배양&domainTypes=NOTE,PROTOCOL&page=1&size=20
4
Search→Redis
캐시 키: SHA256(q + domainTypes + page + userId + orgId) → GET cache:{hash} 캐시 히트 (3분 TTL) → 즉시 응답
5
Search→OpenSearch
bool 쿼리: must: multi_match (title^4, tags^3, summary^2, content^1, fuzziness:AUTO), filter: orgId + 권한 필터
← 검색 결과 + 하이라이트 스니펫 + domainType별 집계
6
비동기: Search → DB: INSERT INTO searchHistory
Search → Redis: SET cache:{hash} {results} EX 180 (3분 캐시)
7
← {results[], counts:{NOTE:12, PROTOCOL:3}, pagination, took}
→ Frontend: 검색 결과 목록 + 도메인별 탭 카운트 표시

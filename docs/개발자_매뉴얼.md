### 4.5 컨트롤러 패턴

```typescript
import { FastifyRequest, FastifyReply } from 'fastify';
import { AppError, ErrorCode, getOrgId, withOrgScope } from '@lab/shared';
import prisma from '../lib/prisma';

export async function getNotes(request: FastifyRequest, reply: FastifyReply) {
  const orgId = getOrgId(request.headers);
  const userId = request.headers['x-user-id'] as string;
  const { status, page = '1', limit = '20' } = request.query as Record<string, string>;

  const where = withOrgScope({
    deletedAt: null,
    ...(status && { status }),
  }, orgId);

  const [notes, total] = await Promise.all([
    prisma.note.findMany({
      where,
      orderBy: { createdAt: 'desc' },
      skip: (parseInt(page) - 1) * parseInt(limit),
      take: parseInt(limit),
    }),
    prisma.note.count({ where }),
  ]);

  return reply.send({ ok: true, data: notes, total });
}

export async function deleteNote(request: FastifyRequest, reply: FastifyReply) {
  const { id } = request.params as { id: string };
  const orgId = getOrgId(request.headers);

  const note = await prisma.note.findFirst({ where: { id, orgId, deletedAt: null } });
  if (!note) throw new AppError(404, '노트를 찾을 수 없습니다.', ErrorCode.NOTE_NOT_FOUND);

  if (note.status === 'signed' || note.status === 'locked') {
    throw new AppError(400, '서명/잠금된 노트는 삭제할 수 없습니다.', ErrorCode.NOTE_LOCKED);
  }

  // Soft delete
  await prisma.note.update({ where: { id }, data: { deletedAt: new Date() } });

  return reply.send({ ok: true, data: { id } });
}
```

### 4.7 Prisma 사용 패턴

```typescript
// lib/prisma.ts — Soft delete 미들웨어
const prisma = new PrismaClient();

// findFirst, findMany, count에 자동으로 deletedAt: null 조건 추가
prisma.$use(async (params, next) => {
  if (['Note'].includes(params.model) && ['findFirst', 'findMany', 'count'].includes(params.action)) {
    if (params.args.where?.deletedAt === undefined) {
      params.args.where = { ...params.args.where, deletedAt: null };
    }
  }
  return next(params);
});

export default prisma;
```

## 5. API Gateway

**위치**: `services/api-gateway/src/`

### 5.1 JWT 검증 흐름

```
1. 모든 요청에서 x-user-*, x-internal-secret 헤더 제거 (스푸핑 방지)
2. PUBLIC_PATHS (/health, /api/auth/login, /api/auth/refresh 등) → 통과
3. /internal/ 경로 → 404 차단
4. Authorization: Bearer <token> 추출
5. Redis 토큰 블랙리스트 확인
6. jose.jwtVerify(token, JWT_SECRET)
7. Redis 사용자 블랙리스트 확인 (권한 변경 시 기존 토큰 무효화)
8. 검증된 claims → 헤더 주입:
   - x-user-id, x-user-role, x-user-email
   - x-user-permissions (JSON 배열)
   - x-user-org-id
   - x-user-team-ids (JSON 배열)
   - x-user-team-roles (JSON 맵)
```

## 6. Redis 이벤트 시스템

### 6.1 이벤트 흐름

```
[Publisher] → Redis Stream (labnote:events) → [Consumer Group] → [Handler]
```

### 6.2 이벤트 타입

| 이벤트 | 발행자 | 구독자 | 설명 |
|--------|--------|--------|------|
| NOTE_SIGNED | signature-audit-service | eln-service | 노트 status → signed |
| NOTE_DELETED | eln-service | search, signature | 인덱스/서명 정리 |
| USER_DELETED | auth-service | eln, inventory, search | 관련 데이터 비활성화 |
| USER_SUSPENDED | auth-service | eln, inventory, search | 사용자 비활성화 |

### 6.3 발행 패턴

```typescript
import { buildServiceEvent, ServiceEventType } from '@lab/shared';

const event = buildServiceEvent(
  ServiceEventType.NOTE_SIGNED,
  'signature-audit-service',
  noteId,
  { noteId, signerId: userId, signatureId: sigId }
);

await redis.xadd('labnote:events', '*', 'type', event.type, 'data', JSON.stringify(event));
```

### 6.4 소비 패턴

```typescript
// Consumer Group 생성
await redis.xgroup('CREATE', 'labnote:events', 'eln-service', '$', 'MKSTREAM');

// 이벤트 읽기 루프
while (running) {
  const messages = await redis.xreadgroup(
    'GROUP', 'eln-service', `eln-${process.pid}`,
    'BLOCK', 5000, 'COUNT', 10,
    'STREAMS', 'labnote:events', '>'
  );

  for (const [msgId, fields] of messages) {
    const data = parseFields(fields);

    if (data.type === 'NOTE_SIGNED') {
      await handleNoteSigned(data);  // 멱등성 보장
    }

    await redis.xack('labnote:events', 'eln-service', msgId);
  }
}
```

**핵심 원칙:**
- **멱등성**: 같은 이벤트를 여러 번 처리해도 결과가 동일해야 함
- **Pending 복구**: 60초마다 미처리 메시지 재시도 (최대 5회)
- **비차단**: 이벤트 소비 실패가 메인 서비스에 영향을 주지 않음

## 8. 인증/권한 체계

### 8.1 전체 흐름

```
1. 로그인 → auth-service가 JWT 발급 (claims: sub, role, permissions, orgId, teams)
2. 요청 → api-gateway가 JWT 검증 → 내부 헤더 주입
3. 서비스 → requireAuth (x-user-id 존재 확인)
          → requirePermission (x-user-permissions 포함 확인)
          → requireRole (x-user-role 일치 확인)
4. 데이터 → withOrgScope(where, orgId) (멀티테넌시 필터)
```

### 8.2 서비스 간 통신

```typescript
// 내부 API 호출 시
const res = await fetch(`${AUTH_SERVICE_URL}/api/auth/internal/verify-password`, {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'x-internal-secret': process.env.INTERNAL_SECRET,
  },
  body: JSON.stringify({ userId, password }),
});
```

### 8.3 멀티테넌시 규칙

**모든 데이터 쿼리에 orgId 필터 필수** — 누락 시 데이터 유출.

```typescript
// 모든 Prisma where절
const where = withOrgScope({ status: 'draft' }, orgId);
// → { status: 'draft', orgId: 'org-xxx' }
```

## 9. 노트 상태 머신

### 9.1 상태 전환 규칙

```
              ┌───────────┐    ┌──────────────┐    ┌────────┐
              │   draft   │◄──►│ in_progress  │───►│ locked │
              │   (초안)   │    │   (진행 중)   │    │  (잠김) │
              └───────────┘    └──────┬───────┘    └───┬────┘
                                     │                 │
                                서명 서비스           관리자 잠금해제
                              (Redis Stream)       (비밀번호 확인)
                                     │                 │
                                ┌────▼───┐        ┌───▼────┐
                                │ signed │        │  draft  │
                                │(서명완료)│        └────────┘
                                └────────┘
```

### 9.2 전환 맵 (코드)

```typescript
// 일반 사용자 (dtos/note.dto.ts)
ALLOWED_STATUS_TRANSITIONS = {
  draft: ['in_progress'],
  in_progress: ['draft', 'locked'],
  signed: [],
  locked: [],
};

// 시스템 (서명 이벤트 처리)
SYSTEM_STATUS_TRANSITIONS = {
  draft: ['in_progress'],
  in_progress: ['draft', 'signed', 'locked'],
  signed: [],
  locked: [],
};
```

### 9.3 핵심 제약

- `signed` 전환: **서명 프로세스만 가능** (PATCH /status로 직접 불가)
- `signed` 상태: **영구 불변** (어떤 역할도 되돌릴 수 없음)
- `locked` 전환: **Reviewer/Admin만** (컨트롤러에서 x-user-role 검증)
- `locked` → `draft`: **Admin만** (별도 `/admin-unlock` 엔드포인트 + 비밀번호)
- DB 트리거 `check_note_status_transition()`가 최종 안전장치 — **수정 금지**
- 모든 상태 변경: `NoteStatusHistory` + `AuditLog` **이중 기록**

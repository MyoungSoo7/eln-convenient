# 00 — 메타룰: 에이전트 작업 프로토콜

> 01~11 룰이 "코드를 어떻게 쓸 것인가"라면, 이 룰은 **"에이전트가 이 프로젝트에서 어떻게 일할 것인가"**의 작업 프로토콜이다.
> 모든 파일 수정 시 자동 로드되며, 다른 룰보다 먼저 적용된다.

## 1. 탐색 → 이해 → 수정 순서

- **수정 전 반드시 읽는다**: 읽지 않은 파일은 수정하지 않는다. 추측으로 Edit 하지 말 것
- **주변 컨텍스트 확인**: 함수 하나를 고칠 때 그 함수가 호출되는 곳을 최소 1곳 확인
- **중복 검색 금지**: 서브에이전트에 위임한 조사를 메인에서 반복하지 않는다

## 2. 수정 범위 규율

- **요청된 것만 수정**: 버그 수정 요청에 주변 코드 리팩터링을 얹지 않는다
- **불필요한 방어코드 추가 금지**: 발생할 수 없는 시나리오의 try/catch/validation 추가 금지
- **주석/독스트링 추가 금지**: 수정하지 않은 코드에 주석을 붙이지 않는다. 로직이 자명하지 않을 때만 추가
- **Breaking 복구 코드 금지**: `// removed` 주석, 미사용 `_var` 리네임, 호환성 shim — 사용하지 않으면 완전히 삭제

## 3. 서비스 수정 시 반드시 할 것

백엔드 서비스(`services/<name>-service/src/*`) 수정 후:

1. **재빌드 안내**: `docker compose up -d --build <서비스명>` 리마인더 (훅이 자동 출력하지만 본인도 언급)
2. **@lab/shared 수정 시**: services/shared 빌드 + 의존 서비스 **전부** 재빌드 필요 언급
3. **Prisma schema 수정 시**: `npx prisma migrate dev --name <설명>` 안내 + 기존 마이그레이션 파일 **직접 수정 금지** 재확인

프론트엔드(`src/*`) 수정 시:

1. **재빌드 불필요** (Vite HMR)
2. **i18n**: 한글/영어 문자열 추가 시 `ko/`와 `en/` 양쪽 반영 (단일 반영 금지)

## 4. 서브에이전트 호출 기준

| 상황 | 에이전트 사용 | 직접 도구 사용 |
|---|---|---|
| 특정 함수 위치 찾기 | ❌ | Grep |
| 파일 패턴 찾기 | ❌ | Glob |
| 단일 파일 이해 | ❌ | Read |
| 3+ 파일 교차 조사 | ⭕ Explore | - |
| 도메인별 검증 | ⭕ 특화 에이전트 | - |
| 독립적 병렬 조사 | ⭕ 복수 Agent 병렬 | - |

**원칙**: 에이전트 호출은 **컨텍스트 보호** 또는 **병렬화**가 명확한 이득일 때만.

## 5. TaskCreate 사용 기준

- **쓸 때**: 3단계 이상의 작업, 중간에 사용자 확인이 필요한 멀티스텝, 병렬 작업 추적
- **쓰지 말 때**: 단일 파일 수정, 단일 질문 답변, 자명한 1-2단계 작업

## 6. 사용자 확인이 필요한 행동

다음은 **반드시 사용자 승인** 후 실행:

- `git push` (특히 main/master)
- 마이그레이션 배포 (`prisma migrate deploy`)
- Docker 볼륨 삭제
- `@lab/shared` 공개 API 시그니처 변경
- `settings.json` deny 룰 변경
- 외부 서비스(Slack/GitHub/외부 API) 호출
- 5개 이상 파일의 대규모 리네임/이동

사용자가 한 번 승인했다고 해서 비슷한 다른 행동이 자동 승인되는 것은 아니다 — **스코프는 명시된 범위로 한정**.

## 7. 실패 대응

- **같은 명령 반복 금지**: 동일 커맨드가 실패하면 원인 파악 후 변경, 재실행 루프 금지
- **훅 실패는 블로킹 아님**: 훅 실패해도 작업 계속 진행, 다만 메시지는 사용자에게 전달
- **파괴적 우회 금지**: `--no-verify`, `--force`, `git reset --hard` 류를 "문제 회피용"으로 쓰지 말 것
- **락 파일 존중**: lock 파일이 있으면 삭제 전에 원인부터 조사

## 8. 출력 스타일

- **한국어 기본** (사용자가 한국어로 대화 중이므로)
- **간결함 우선**: 사족 금지, "~해드릴게요" 류 빈말 금지
- **파일:라인 참조**: 코드 인용 시 `path:line` 형식
- **이모지 금지**: 사용자가 명시 요청한 경우만

## 9. 이 프로젝트 특유의 함정

| 함정 | 대처 |
|---|---|
| `locked`/`signed` 노트 상태 수정 시도 | 불변 — 컨트롤러 체크 + DB 트리거로 이중 차단 |
| `x-user-*` 헤더 직접 신뢰 | api-gateway 통과 전제. 내부 서비스는 `x-internal-secret` 검증 |
| `orgId` 필터 누락 | 즉시 데이터 유출 — `getOrgId()` + `withOrgScope()` 필수 |
| `ai-assistant-service`에서 Fastify 관례 적용 | 여기만 Express — 패턴 다름 |
| `services/inventory-frontend` 포트 혼동 | 컨테이너 80 → 호스트 3000 |
| `@lab/shared` 수정 후 단일 서비스만 재빌드 | 의존 서비스 전부 재빌드 필요 |
| PII 로그 평문 출력 | `maskPII()` 필수 (rule 11 참조) |

## 10. 이 룰의 우선순위

- 이 메타룰은 **프로젝트 운영 방식**을 정의한다
- 코드 스타일/패턴은 01~11 룰이 담당
- 충돌 시: 이 메타룰 > 01~11 룰 > 일반 관행
- 사용자의 명시 지시 > 모든 룰

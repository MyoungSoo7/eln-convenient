## 1. 시스템 개요

LabNote ELN은 연구실에서 사용하는 전자연구노트 협업 플랫폼입니다.

### 주요 기능

| 기능 | 설명 |
|------|------|
| 연구노트 작성 | 노트 작성, 편집, 버전 관리, 실시간 협업 |
| 전자서명 | SHA-256 해시체인 기반 전자서명, 무결성 검증 |
| 프로토콜/템플릿 | 실험법, SOP 템플릿 관리 및 공유 |
| 인벤토리 관리 | 시약, 샘플, 장비 재고 추적 및 알림 |
| 장비/회의실 예약 | 예약 생성, 승인/반려, 캘린더 뷰 |
| 통합 검색 | 노트, 템플릿, 인벤토리 통합 검색 (한국어 지원) |
| 감사 로그 | 모든 활동 기록 및 추적 |
| 내보내기 | PDF, ZIP, 보고서 형식 내보내기 |
| 실시간 알림 | 서명, 잠금, 예약 승인 등 실시간 알림 |

### 접속 URL

| 용도 | URL |
|------|-----|
| 메인 프론트엔드 | http://localhost:5173 |
| 인벤토리 전용 프론트엔드 | http://localhost:3000 |

## 2. 접속 및 로그인

### 2.1 로그인

1. 브라우저에서 `http://localhost:5173`에 접속합니다.
2. 이메일과 비밀번호를 입력합니다.
3. **로그인** 버튼을 클릭합니다.
4. 로그인에 성공하면 대시보드로 이동합니다.

### 2.2 로그아웃

1. 우측 상단의 **사용자 아바타**를 클릭합니다.
2. 드롭다운 메뉴에서 **로그아웃**을 선택합니다.

### 2.3 언어 설정

- 헤더 영역의 **언어 전환 버튼**으로 한국어/영어를 전환할 수 있습니다.
- 로그인 화면에서도 언어 전환이 가능합니다.

### 2.4 테마 설정

- 헤더 영역의 **테마 토글 버튼**으로 라이트/다크 모드를 전환할 수 있습니다.

## 4. 대시보드

로그인 후 가장 먼저 보이는 화면입니다. 현재 작업 상황을 한눈에 파악할 수 있습니다.

### 4.1 내 대시보드

모든 사용자에게 표시됩니다.

- **통계 카드 (4개)**
  - 전체 노트 수
  - 진행 중 노트 수
  - 인벤토리 아이템 수
  - 대기 중인 예약 / 미읽은 알림 수
- **최근 노트**: 최근 수정한 노트 4건 (상태 뱃지 포함, 클릭하면 해당 노트로 이동)
- **예정 예약**: 다가오는 예약 4건 (승인/대기 뱃지 포함)
- **최근 활동**: 최근 감사 로그 4건
- **알림**: 재고 부족/만료 임박 인벤토리 항목 최대 5건

### 4.2 조직 대시보드 (Admin 전용)

Admin 역할인 경우 탭 전환으로 조직 전체 현황을 볼 수 있습니다.

- 전체 노트 통계 (상태별)
- 규정 준수율 (서명 완료 비율)
- 인벤토리 현황 (총 수량, 재고 부족, 만료 임박)
- 예약 현황
- 최근 조직 활동

> 대시보드 데이터는 60초마다 자동 갱신됩니다.

## 5. 연구노트

### 5.1 노트 목록 (`/notes`)

#### 노트 조회

- **상태 필터**: 전체 / 초안(draft) / 진행 중(in_progress) / 서명 완료(signed) / 잠김(locked)
- **검색**: 제목 또는 태그로 검색
- **템플릿 필터**: 프로토콜 페이지에서 "노트 보기"를 클릭하면 해당 템플릿으로 생성된 노트만 표시

#### 노트 생성

1. **"새 노트"** 버튼을 클릭합니다.
2. 노트 편집기(`/notes/new`)로 이동합니다.
3. 제목과 내용을 입력합니다.
4. **저장** 버튼을 클릭합니다.

> 프로토콜에서 "노트 작성"을 선택하면 템플릿 내용이 미리 채워진 상태로 새 노트가 생성됩니다.

#### 노트 상태 전환 (목록에서)

각 노트 카드의 드롭다운 메뉴에서 상태를 변경할 수 있습니다.

| 현재 상태 | 변경 가능한 상태 | 필요 역할 |
|-----------|-----------------|-----------|
| 초안 → | 진행 중 | 모든 역할 |
| 진행 중 → | 초안 | 모든 역할 |
| 진행 중 → | 잠김 | Reviewer, Admin |
| 잠김 → | 초안 (잠금 해제) | Admin (비밀번호 필요) |

#### 노트 삭제

- 초안(draft) 또는 진행 중(in_progress) 상태의 노트만 삭제할 수 있습니다.
- 잠김(locked) 또는 서명 완료(signed) 상태의 노트는 삭제할 수 없습니다.
- 노트 카드에 마우스를 올리면 휴지통 아이콘이 나타납니다.
- 삭제 전 확인 대화상자가 표시됩니다.

### 5.2 노트 편집기 (`/notes/:id`)

#### 기본 편집

- **제목**: 상단 입력 필드에서 수정
- **내용**: 본문 텍스트 영역에서 자유롭게 작성
- **저장**: "저장" 버튼 클릭 (수정 시 자동으로 리비전 생성)
- **상태 뱃지**: 현재 상태가 헤더에 표시
- **"진행 시작" 버튼**: 초안 상태에서 클릭하면 진행 중으로 전환

> 잠김(locked) 또는 서명 완료(signed) 상태에서는 편집이 비활성화됩니다.

#### 실시간 협업

- 같은 노트를 여러 사용자가 동시에 열면 **실시간 협업 모드**가 활성화됩니다.
- 접속 중인 사용자의 **색상 아바타**가 상단에 표시됩니다.
- 다른 사용자의 편집 내용이 실시간으로 반영됩니다.
- 커서 위치(awareness)가 공유됩니다.

#### 탭 기능

**편집기 탭** (기본)
- 노트 내용을 작성하고 편집하는 메인 영역

**첨부파일 탭**
- 드래그 앤 드롭 또는 클릭하여 파일을 업로드합니다.
- 업로드된 파일 목록: 파일명, MIME 타입, 크기, 날짜
- 파일 클릭으로 다운로드/열기
- 마우스 오버 시 삭제(휴지통) 아이콘 표시
- 새 노트(저장 전) 또는 잠긴 노트에서는 업로드 비활성화

**연결 탭 (시약/장비 연결)**
- 노트에 인벤토리 아이템을 연결할 수 있습니다.
- **"시약/장비 연결"** 버튼 → 인벤토리 검색 대화상자에서 검색 후 클릭하여 연결
- 연결된 아이템: 유형 뱃지 + 이름 표시
- X 버튼으로 연결 해제
- 새 노트(저장 전) 또는 잠긴 노트에서는 비활성화

**버전 이력 탭**
- 탭 최초 클릭 시 이력을 불러옵니다.
- 타임라인 형태로 표시: 버전 번호, 시간, 변경 요약, 변경자

#### 전자서명 (노트 편집기에서)

진행 중(in_progress) 상태에서 **"서명"** 버튼이 표시됩니다 (Reviewer/Admin만).

1. "서명" 버튼 클릭
2. 비밀번호 입력 대화상자에서 본인 비밀번호 입력
3. 서명이 완료되면 노트 상태가 자동으로 **서명 완료(signed)**로 전환
4. 서명 완료 후에는 수정/삭제가 불가능합니다.

## 6. 프로토콜 (템플릿)

프로토콜은 반복 사용하는 실험 절차나 SOP를 템플릿으로 관리하는 기능입니다.

### 6.1 프로토콜 목록 (`/protocols`)

- **검색**: 제목 또는 카테고리로 검색
- 프로토콜 카드에 카테고리 뱃지, 태그, 사용 횟수("N회 사용됨")가 표시됩니다.

### 6.2 프로토콜 생성

1. **"새 템플릿"** 버튼 클릭
2. 다음 항목을 입력합니다:
   - **제목** (필수)
   - **카테고리** (일반, 실험법, 분석법, 품질관리, SOP, 안전절차 등)
   - **설명**
   - **내용** (템플릿 본문)
   - **태그**
   - **공개 여부** (공개 시 다른 조직에서도 조회 가능)
3. **저장** 클릭

### 6.3 프로토콜 활용

| 기능 | 설명 |
|------|------|
| **노트 작성** | 프로토콜 카드의 "노트 작성" → 템플릿 내용이 미리 채워진 새 노트 생성 |
| **노트 보기** | "노트 보기" → 이 프로토콜로 생성된 노트 목록으로 이동 |
| **복사** | 프로토콜을 복사하여 새 프로토콜 생성 (원본의 복사 횟수 증가) |
| **편집** | 연필 아이콘 → 수정 대화상자 (소유자 또는 관리자만) |
| **삭제** | 확인 후 삭제 (소유자 또는 관리자만) |

## 7. 인벤토리

시약, 샘플, 장비 등 연구실 물품을 관리하는 기능입니다.

### 7.1 인벤토리 목록 (`/inventory`)

#### 알림 배너

목록 상단에 다음 알림이 표시됩니다:
- **만료 임박 아이템 수**: 클릭하면 만료 임박 아이템 필터링
- **재고 부족 아이템 수**: 클릭하면 재고 부족 아이템 필터링

#### 필터 및 검색

- **유형 탭**: 시약, 샘플, 장비, 소모품, 항체, 플라스미드, 세포주 등 (동적 로드)
- **상태 필터**: 사용 가능 / 사용 중 / 소진 / 만료 / 폐기 / 유지보수
- **텍스트 검색**: 이름으로 검색 (300ms 디바운스)

#### 표시 정보

| 열 | 설명 |
|----|------|
| 항목명 | 이름 + 태그 뱃지 (최대 3개) |
| 유형 | 시약, 샘플, 장비 등 |
| 상태 | 색상 뱃지 |
| 카테고리 | 분류 |
| 수량 | 숫자 + 단위 (재고 부족 시 경고 표시) |
| 위치 | 보관 장소 |
| 유효기간 | 날짜 (만료 시 빨간색, N일 남음 시 주황색) |
| 등록일 | 생성 날짜 |

### 7.2 아이템 추가

1. **"항목 추가"** 버튼 클릭
2. 다음 항목을 입력합니다:

| 필드 | 필수 | 설명 |
|------|------|------|
| 이름 | O | 아이템명 |
| 유형 | O | 시약, 샘플, 장비 등 |
| 위치 | | 보관 장소 |
| 수량 | | 초기 수량 |
| 단위 | | mL, g, EA 등 |
| 바코드 | | 고유 바코드 번호 |
| 최소 수량 | | 이 값 이하 시 재고 부족 알림 |
| 유효기간 | | 만료일 |
| 만료 경고 일수 | | 만료 N일 전부터 경고 (기본 30일) |
| 태그 | | 분류 태그 (여러 개 가능) |

### 7.3 아이템 상세 조회

아이템 행을 클릭하면 상세 정보 대화상자가 열립니다.
- 모든 필드 정보 표시
- **변경 이력 테이블**: 날짜, 변경 유형, 이전/이후 수량, 이전/이후 상태, 사유, 수행자

### 7.4 수량 조정

1. 아이템 행의 **수량 조정(↕)** 버튼 클릭
2. 변경 유형 선택:
   - **입고(in)**: 수량 증가
   - **출고(out)**: 수량 감소
   - **조정(adjust)**: 절대값으로 설정
3. 수량 입력
4. 사유 입력 (선택)
5. "이전 수량 → 변경 후 수량" 미리보기 확인
6. **확인** 클릭

### 7.5 아이템 수정/삭제

- **수정**: 연필 아이콘 클릭 → 편집 대화상자 (유형은 수정 불가)
- **삭제**: 휴지통 아이콘 클릭 → 확인 후 삭제

### 7.6 바코드 조회

바코드 번호로 아이템을 직접 조회할 수 있습니다 (API: `GET /api/inventory/items/barcode/:barcode`).

## 8. 장비/회의실 예약

### 8.1 예약 탭 (`/scheduler`)

#### 캘린더 뷰

- **주간 캘린더**: 월~일, 08:00~17:00 시간 슬롯
- 승인(APPROVED)된 예약: 파란색, 대기(PENDING) 예약: 노란색
- **주 이동**: 이전/다음 주 화살표, "오늘" 버튼

#### 예약 생성

1. **"새 예약"** 버튼 클릭
2. 다음 항목을 입력합니다:
   - **자원 선택**: 장비 또는 회의실 목록에서 선택
   - **제목/용도**: 예약 목적
   - **날짜**: 예약 날짜
   - **시작 시간 / 종료 시간**: 사용 시간대
3. **예약** 클릭
4. 예약이 **대기(PENDING)** 상태로 생성됩니다.

> 같은 자원의 같은 시간대에 이미 승인/대기 중인 예약이 있으면 충돌 오류가 발생합니다.

#### 예약 목록

- **상태 필터 탭**: 전체 / 대기 중 / 승인됨
- 각 예약에 자원명, 일시, 상태 뱃지 표시

#### 예약 승인/반려 (Reviewer, Admin 또는 자원 담당자)

대기(PENDING) 상태의 예약에 다음 버튼이 표시됩니다:

- **승인**: 클릭 시 즉시 승인 (DB 레벨 충돌 재검증 후 처리)
- **반려**: 클릭 시 사유 입력 대화상자 → 반려 처리

#### 예약 상태 흐름

```
PENDING ──► APPROVED ──► COMPLETED
   │            │
   │            └──► CANCELLED
   │
   ├──► REJECTED
   │
   └──► CANCELLED
```

| 현재 | 가능한 전환 | 수행 가능한 역할 |
|------|------------|----------------|
| PENDING | APPROVED | Admin, 자원 담당자(ownerId) |
| PENDING | REJECTED | Admin, 자원 담당자(ownerId) |
| PENDING | CANCELLED | 예약자 본인, Admin |
| APPROVED | COMPLETED | 예약자 본인, Admin |
| APPROVED | CANCELLED | 예약자 본인, Admin |

### 8.2 자원 관리 탭 (Admin 전용)

#### 자원 조회

- 장비(EQUIPMENT) / 회의실(ROOM) 필터
- 목록: 이름, 유형, 위치, 수용 인원(회의실), 설명

#### 자원 등록

1. **"자원 등록"** 버튼 클릭
2. 항목 입력:
   - **유형**: 장비 / 회의실
   - **이름** (필수)
   - **위치**
   - **설명**
   - **수용 인원** (회의실만)
   - **승인 담당자** (지정 안 하면 Admin이 승인)

#### 자원 수정/비활성화

- **수정**: 이름, 위치, 설명 등 변경
- **비활성화**: 대기/승인된 예약이 있는 자원은 비활성화할 수 없습니다.

**문서 즐겨찾기**
- 노트, 템플릿, 인벤토리 문서를 즐겨찾기에 추가 가능 (API 지원)

## 10. 전자서명 및 규정 준수

### 10.1 서명 현황 (`/signatures`)

#### 요약 카드

- **서명 완료**: 서명된 노트 수
- **서명 대기**: 초안 + 진행 중 노트 수
- **잠긴 노트**: 잠김 상태 노트 수

#### 노트 목록 및 작업

| 노트 상태 | 표시 버튼 | 동작 |
|-----------|----------|------|
| 서명 완료 / 잠김 | "열람" | 노트 읽기 전용 보기 |
| 진행 중 | "서명" | 노트 편집기로 이동 (서명 가능) |
| 초안 | "수정" | 노트 편집기로 이동 |

### 10.2 전자서명 프로세스

#### 서명 요건

- **노트 상태**: 반드시 **진행 중(in_progress)**이어야 합니다.
- **역할**: **Reviewer** 또는 **Admin**만 서명할 수 있습니다 (Researcher는 `note:sign` 권한 없음).
- **비밀번호 확인**: 서명 시 본인 비밀번호를 입력해야 합니다.

#### 서명 흐름

1. 노트 편집기에서 **"서명"** 버튼 클릭
2. 비밀번호 입력 대화상자에서 비밀번호 입력
3. 시스템이 다음을 수행합니다:
   - 비밀번호 검증 (auth-service)
   - 노트 내용의 SHA-256 해시 계산
   - 이전 서명의 해시와 체이닝 (해시체인)
   - 서명 레코드 저장
   - 노트 상태를 **서명 완료(signed)**로 자동 전환
4. 서명 완료된 노트는 **영구 불변** — 수정, 삭제, 상태 변경이 모두 불가합니다.

#### 서명 검증

`GET /api/signatures/verify/:noteId` API를 통해 해시체인의 무결성을 검증할 수 있습니다.

#### 규정 준수 통계 (Admin)

조직 대시보드에서 다음을 확인할 수 있습니다:
- 전체 노트 대비 서명 완료 비율 (complianceRate)
- 서명 완료 / 미서명 노트 수

### 10.3 중요 제약사항

| 규칙 | 설명 |
|------|------|
| 서명은 서명 프로세스만 가능 | `PATCH /status`로 직접 "signed"로 변경 불가 |
| 서명 완료 = 영구 불변 | 어떤 역할도 되돌릴 수 없음 |
| Researcher는 서명 불가 | `note:sign` 권한이 없음 |
| DB 안전장치 | `check_note_status_transition()` 트리거가 잘못된 전환 차단 |

## 11. 감사 로그

### 11.1 감사 로그 조회 (`/audit-logs`)

모든 시스템 활동이 자동으로 기록됩니다.

#### 필터

- **검색**: 수행자(actor) ID로 검색

| IP | 요청 IP 주소 |

#### 페이지네이션

- 페이지당 20건
- 이전/다음 페이지 이동
- 현재 범위 표시 (예: "1~20 / 150건")

### 11.2 기록되는 활동

| eln | 노트 생성, 수정, 상태 변경, 잠금 해제, 삭제 |
| sig-audit | 전자서명, 서명 철회, 내보내기 요청 |

## 12. 내보내기

### 12.1 내보내기 페이지 (`/exports`)

서명 완료(signed) 또는 잠김(locked) 상태의 노트를 PDF, ZIP 형식으로 내보낼 수 있습니다.

#### 전체 ZIP 내보내기

- **"전체 ZIP 내보내기"** 카드: 대상 노트 수가 표시됩니다.
- 클릭하면 모든 서명/잠금 노트를 하나의 ZIP 파일로 내보냅니다.

#### 개별 노트 내보내기

서명/잠금 노트 목록에서 각 노트마다:
- **PDF 버튼**: 해당 노트를 PDF로 내보내기
- **ZIP 버튼**: 해당 노트를 ZIP으로 내보내기

#### 내보내기 진행 상태

- 내보내기를 요청하면 **진행 중** 섹션에 스피너와 함께 상태가 표시됩니다.
- 3초마다 자동으로 상태를 폴링합니다.
- 완료 시 **"다운로드"** 링크가 표시됩니다.
- 실패 시 오류 메시지가 표시됩니다.

#### 내보내기 처리 과정 (내부)

1. 요청 접수 → BullMQ 큐에 작업 등록
2. 워커가 노트 내용 조회 → Puppeteer로 PDF 렌더링
3. 결과 파일을 MinIO에 업로드
4. SSE(Server-Sent Events)를 통해 실시간으로 완료 알림 전달

## 13. 알림

### 13.1 실시간 알림

헤더 우측의 **종(🔔) 아이콘**을 클릭하면 알림 패널이 열립니다.

#### 알림 유형

| 유형 | 발생 시점 | 수신자 |
|------|----------|--------|
| NOTE_LOCKED | 노트가 잠금 상태로 변경될 때 | 관련 사용자 |
| NOTE_SIGNED | 노트에 전자서명이 완료될 때 | 관련 사용자 |
| NOTE_UNLOCKED | 관리자가 노트 잠금을 해제할 때 | 관련 사용자 |
| BOOKING_APPROVED | 예약이 승인될 때 | 예약 요청자 |

#### 알림 기능

- **미읽은 알림 수**: 종 아이콘 위에 뱃지로 표시
- **알림 패널**: 최근 알림 목록 (유형, 제목, 내용, 시간)
- **읽음 처리**: 개별 알림 또는 전체 읽음 처리
- **이동**: 노트 알림 클릭 → 해당 노트로 이동, 예약 알림 클릭 → 예약 페이지로 이동

> 알림은 30초마다 폴링하며, SSE 연결이 가능하면 실시간으로 수신됩니다.

## 16. 노트 상태 흐름 상세

### 16.1 상태 다이어그램

```
┌──────────┐       ┌───────────────┐       ┌─────────┐
│  draft   │◄─────►│  in_progress  │──────►│  locked │
│  (초안)   │       │   (진행 중)     │       │  (잠김)  │
└──────────┘       └───────┬───────┘       └────┬────┘
                           │                    │
                      서명 프로세스            Admin 잠금 해제
                    (Reviewer/Admin)        (비밀번호 필요)
                           │                    │
                      ┌────▼────┐          ┌────▼────┐
                      │ signed  │          │  draft  │
                      │(서명완료) │          └─────────┘
                      └─────────┘
                      ※ 되돌릴 수 없음
```

### 16.2 전환 규칙 요약

| 전환 | 방법 | 필요 역할 | API |
|------|------|-----------|-----|
| draft → in_progress | 직접 | 모든 역할 | `PATCH /api/notes/:id/status` |
| in_progress → draft | 직접 | 모든 역할 | `PATCH /api/notes/:id/status` |
| in_progress → locked | 직접 | Reviewer, Admin | `PATCH /api/notes/:id/status` |
| in_progress → signed | 서명 프로세스 | Reviewer, Admin (`note:sign`) | `POST /api/signatures/sign/:noteId` |
| locked → draft | 관리자 잠금 해제 | Admin (`note:unlock`) | `POST /api/notes/:id/admin-unlock` |
| signed → (모든 상태) | **불가** | — | — |

### 16.3 상태별 제약

| 상태 | 편집 | 삭제 | 상태 변경 | 서명 |
|------|:----:|:----:|:---------:|:----:|
| draft | O | O | O | X (in_progress에서만) |
| in_progress | O | O | O | O (Reviewer/Admin) |
| locked | **X** | **X** | Admin만 해제 가능 | X |
| signed | **X** | **X** | **불가** | X (이미 서명됨) |

## 17. 자주 묻는 질문

### Q1. 서명 완료된 노트를 수정할 수 있나요?

**아니요.** 서명 완료(signed) 상태는 영구 불변입니다. 어떤 역할도 수정, 삭제, 상태 변경을 할 수 없습니다. 이는 연구 데이터의 무결성을 보장하기 위한 설계입니다.

### Q2. 잠긴 노트를 수정하려면 어떻게 하나요?

Admin 역할의 사용자가 **잠금 해제**를 수행해야 합니다.
1. 노트 목록에서 잠긴 노트의 메뉴 → "잠금 해제" 클릭
2. Admin 비밀번호 입력
3. 사유 입력 (선택)
4. 잠금 해제 후 노트가 초안(draft) 상태로 돌아갑니다.

### Q3. Researcher 역할로 서명을 할 수 있나요?

**아니요.** Researcher 역할에는 `note:sign` 권한이 없어 서명 요청 자체가 불가합니다. 서명은 Reviewer 또는 Admin만 수행할 수 있습니다.

### Q4. 예약 충돌은 어떻게 처리되나요?

예약 생성 시 같은 자원의 같은 시간대에 대기(PENDING) 또는 승인(APPROVED) 상태의 예약이 있으면 충돌 오류가 발생합니다. 승인 시에는 DB 수준의 비관적 락(FOR UPDATE)으로 동시 승인을 방지합니다.

### Q5. 인벤토리 알림은 어떻게 작동하나요?

- **재고 부족**: 아이템의 현재 수량이 **최소 수량(minQuantity)** 이하일 때 경고 표시
- **만료 임박**: 아이템의 유효기간이 **만료 경고 일수(expiryWarningDays, 기본 30일)** 이내일 때 경고 표시
- 대시보드의 알림 영역과 인벤토리 목록 상단 배너에 표시됩니다.

### Q6. 내보내기 파일은 어디에 저장되나요?

내보내기된 PDF/ZIP 파일은 **MinIO 오브젝트 스토리지**에 저장됩니다. 내보내기 완료 후 제공되는 다운로드 링크는 시간 제한이 있는 Presigned URL입니다.

### Q7. 검색이 잘 안 됩니다. 왜 그런가요?

검색은 **OpenSearch**를 사용하며, 노트/템플릿/인벤토리를 생성하거나 수정할 때 자동으로 인덱스가 갱신됩니다. 인덱스 갱신은 비동기(fire-and-forget)로 처리되므로, 생성/수정 직후 검색에 반영되기까지 약간의 지연이 있을 수 있습니다.

### Q8. 다국어는 어떻게 전환하나요?

헤더 우측의 **언어 전환(🌐)** 버튼을 클릭하면 한국어(ko)와 영어(en) 사이에서 전환됩니다. 설정은 브라우저에 저장되어 다음 접속 시에도 유지됩니다.
